- Security: a change must be for the site it belongs to. `changes.create` and `changes.updateDraft` refuse a change URL that is not on the site’s primary domain or one of its hosts, with a message naming those hosts, and approval and the apply job enforce the same rule on stored change sets, so a change for another host can no longer resolve through this site’s mapping, edit its repository and be verified against a page it does not serve. An absolute redirect target on another host stays allowed; one on the site’s own host must use the site’s origin.
- Reach: a change set’s traffic at risk resolves every mapping route and redirect source against the site’s origin and normalises it the way Search Console page keys are, so a redirect for `/old/` counts the clicks stored for `https://example.com/old/`, and one page named both by an absolute URL and by its route is counted once. Conflict holds compare the same resolved URLs.
- Fix: recommendation evidence and the facts payload read only the live Search Console connection’s selected property and the web search type, the same rows reach estimates from, so two properties a site connected over its life are no longer added together.
- Security: migration `0012_phase1_fixes.sql` revokes the default PUBLIC execute on `change_set_enqueue` and `recommendation_enqueue` and grants them to the application role, as `crawl_enqueue` already was.
- Tests: the finalize memory bound measures live heap (collection before the baseline and before each sample) instead of raw `heapUsed`, so uncollected garbage no longer reads as retained memory.
