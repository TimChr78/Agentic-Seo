- Every error the command executor returns, audits or writes to the agent ledger is credential-redacted first, and policy reasons are redacted where the policy is made, so a provider answer or an exception can no longer put a token into a response, `agents.activity` or the audit log. Ported from Agentic Marketing v0.14.23 (#885).
- An idempotency key is bound to the caller that first used it: another person or agent presenting the same key answers 409 (`idempotency_key_reused`) instead of receiving the first caller's response. An empty or malformed key is refused instead of being treated as "no key", and a replayed agent write answers its stored response without deciding policy, counting the action or billing a check again. Ported from #906, #930.
- A deduplicated replay of an audited read records the same targets as the call it replays. Ported from #905.
- A writer that races past the advisory locks now gets a readable conflict, not an internal failure: a duplicate active `site_context` and a second published version of one artifact are mapped to `conflict` with one audit entry. Ported from #867, #912.
- One published version per artifact is now also a database constraint (a partial unique index), so a writer that skips the publish lock cannot leave two live versions. Ported from #912.
- Archived artifacts can no longer be published: `artifacts.requestPublish`, `artifacts.requestPublishBundle`, approvals and config imports refuse one with a conflict that names the active singleton when there is one, and an approval whose artifact was archived ends as `rejected` with the reason instead of waiting forever. `artifacts.list` hides archived rows unless `includeArchived: true` is passed and marks each row it returns. Ported from #900.
- Archived singletons are history: a site can archive its site context and create a new one, singleton readers skip the archived row, and `config.import` refuses restoring an archived singleton while an active one exists and otherwise restores it unpublished. Ported from #899.
- `approvals.approve` and a person's pause/resume/revoke take the agent-policy lock first, and the executor re-reads an agent's status under that lock, so a pause committed mid-write cannot slip between a status check and its change. The approval output gains `status: rejected` with a `reason` for the archived case. Ported from #907.
