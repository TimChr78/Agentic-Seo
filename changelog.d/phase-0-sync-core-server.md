- Credential redaction in core: `redactCredentials`, `redactedText`, `safeErrorText` and `providerDiagnostic` (`@agentic-seo/core`) now cover camelCase and PascalCase credential keys, all-capitals names, URL userinfo passwords and every embedded provider token, and redact before text is cut to a length or a line. Ported from Agentic Marketing v0.14.23 (#885, #898, #920).
- `TRUSTED_ORIGINS` wildcards are matched by a bounded glob that cannot run past the host, and a digit-dot wildcard admits a literal IPv4 address only, so `https://192.168.*.*` no longer trusts `https://192.168.evil.com`. A pattern with too many wildcards or too many characters is refused at start-up, naming the entry. Ported from #902.
- A configured URL no longer leaks its credentials into the logs: the API-listening line and the MCP-disabled warning log the origin and path only, and the OTLP exporter is built from the credential-free endpoint with the URL credentials as a Basic header, unless the exporter's own environment headers set Authorization. Ported from #931.
- Every route that reads a request body is guarded: the Better Auth catch-all now refuses a body over 256 KB (including a chunked one without Content-Length), the OAuth consent route has its own 16 KB limit, and a route sweep test fails when a new body-accepting route has no limit. Ported from #932.
- `aseo reset-password` writes the new password and ends every session of that person in one transaction and records the shared `cli` audit entry, so a crash can no longer leave a stolen cookie valid behind a password the operator was told was updated. Ported from #913.
- Unknown `/oauth` paths answer a JSON 404 instead of the admin UI shell, and `/oauth` traffic is its own `/metrics` route group so an identity-provider failure is not counted as an admin UI regression. Ported from #751, #752.
